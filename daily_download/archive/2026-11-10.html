Claude Fable 5.2 tops independent leaderboards; cost per task rises despite cheaper tokens

Anthropic released Claude Fable 5.2 and Mythos 5.2 on Nov 9, sharing an underlying model per the system card. Independent evaluators place Fable 5.2 first on the Artificial Analysis Intelligence Index v5 (65, vs Gemini 4 Carbon 60 and Opus 5.5 59), Epoch's Capabilities Index (174 vs GPT-6 Astra 169) and Arena Code WebDev. What changed
A step up on long-horizon and agentic work: new records on HLE-Diamond (80%), Terminal-Bench-Science (73%) and FrontierCode 2.0 (49%); flat versus Opus 5.5 on Terminal-Bench 4.0 and some document tasks.

high Confirmed Google DeepMind Blog · Nov 10, 07:02

AlphaProof Code: AI agents formally verify Signal's protocol implementation in four weeks

DeepMind's multi-LLM agent framework verified key security properties of the code implementing the Signal protocol, including protection before and after a temporary device compromise. Human experts chose and reviewed every specification, Gemini Carbon-powered agents wrote the Lean proofs, other agents audited them, and about 1% of the codebase was flagged for human review.

What changed
Formal verification of a widely deployed protocol implementation, previously a multi-year expert effort, completed in four weeks with agents producing the proof volume.
Evidence
Vendor claimMachine-checked by Lean. As a test, two previously fixed bugs were reintroduced and the system produced proofs that the buggy versions were insecure. DeepMind is open-sourcing the verification artifacts and published a technical paper.
Opportunity
Formal guarantees for security-critical components (crypto, auth logic, parsers) start to look economical; the human work shifts to writing correct specifications.

Why it matters to you

This changes the cost curve of assurance: for a security architect, 'proven correct against a spec' may become a realistic requirement for small critical components.

Learn
  • Lean and machine-checked proofs
  • Writing security properties as formal specifications

high Confirmed AWS Security Bulletins · Nov 10, 11:42

AWS API MCP Server let agents run AWS operations the operator had denied

AWS bulletin 2026-176-AWS (CVE-2026-125271): the server normalized operation names incorrectly before checking them against the operator's policy, so operations with consecutive capital letters never matched a correctly written denyList or elicitList entry and could run without being blocked or requiring confirmation.

Why it matters to you

A textbook fail-open in agent authorization: the policy layer and the execution layer disagreed on identity of the action, so the operator's controls silently didn't apply.

Action

Update the AWS API MCP Server per the bulletin, and scope the agent's IAM role so a policy-matching bug cannot exceed what the credentials allow.

Learn
  • Canonicalization before authorization checks
  • Capability-scoped credentials for agents

medium Confirmed GitHub Advisories (Go ecosystem) · Nov 10, 10:56

MCP tool surfaces keep bypassing controls enforced only at the HTTP layer

Dagu's fix for an earlier traversal lived in HTTP middleware, but its MCP service calls the API in-process, so viewer-role keys could read arbitrary YAML again. Code Graph RAG's read_file MCP tool joined paths without re-checking containment, and ezBookkeeping's MCP/API IP allowlist trusted a spoofed X-Forwarded-For header.

Why it matters to you

Adding an MCP interface creates a second entry point into existing business logic; authorization or validation that lives in transport middleware is skipped.

Action

Enforce authorization and path containment in the service layer both HTTP and MCP call, and configure trusted proxies before using client IPs for access control.

medium Confirmed GitHub Advisory Database (critical/high) · Nov 10, 10:57

Agent sandboxes fail at the seams: AG2 shell allowlist bypass and Claude Code Edit-tool TOCTOU

AG2's SandboxShellTool checked commands for single-line metacharacters but executed them through sh -c, so an embedded newline bypassed both the allowlist and readonly mode. Separately, Claude Code validated Edit targets with point-in-time path resolution; on macOS a sandboxed process could swap a directory for a symlink so the unsandboxed Edit wrote outside the workspace (fixed in 2.1.251).

Why it matters to you

Both bugs come from validating a representation (a string, a path) rather than the thing actually executed or opened — the core weakness of filter-based agent sandboxes.

Action

Update AG2 and Claude Code; for your own agent tools, avoid shell string execution and use fd-relative, no-follow file operations.

Learn
  • Parser differentials in command allowlists
  • TOCTOU-safe file operations

medium Confirmed GitHub Advisory Database (critical/high) · Nov 09, 16:17

Pocket ID issued client-credentials tokens for arbitrary audiences

Pocket ID's client credentials grant embedded the requested resource as the JWT aud claim without checking that it was a registered resource server or that the client was allowed to request it, so any authenticated OIDC client could mint tokens accepted by other services.

Why it matters to you

Audience binding is what keeps service-to-service tokens from becoming universal keys — the same control matters for agent token exchange.

Action

Update Pocket ID; verify your resource servers reject tokens whose audience they did not register and that your IdP restricts which audiences each client may request.

Learn
  • OAuth resource indicators (RFC 8707) and audience validation

Kubeflow Pipelines cache key ignored namespaces, enabling cross-tenant output substitution

The legacy KFP V1/raw-Argo execution cache did not separate results by Kubernetes namespace, so in multi-user deployments one tenant could receive or seed another tenant's cached step outputs.

Why it matters to you

Shared ML platforms rely on namespaces as the tenant boundary; any shared cache must key on tenant identity or it becomes an integrity channel between teams.

Action

Update Kubeflow Pipelines; in multi-user setups, disable or isolate the V1 cache webhook until patched.

high Confirmed BleepingComputer · Nov 10, 02:49

Fireworks AI breached again via a third-party cloud provider; partial model weights exposed

After an October incident tied to an LLMjacking group, Fireworks disclosed that attackers who compromised a third-party cloud provider hosting its R&D machines reached its development machines on Oct 24. Exposed data included resource metadata, billing information, and incomplete model weights and datasets for some customers; the customer platform showed no further unauthorized access as of Oct 25.

Why it matters to you

Inference platforms hold customers' fine-tuned weights and training data, so their infrastructure providers are part of your model supply chain — an AI-specific twist on third-party risk.

Action

If you use Fireworks, confirm your exposure with them and rotate API keys; review where your fine-tuning data and weights are hosted.
