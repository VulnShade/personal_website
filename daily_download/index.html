high Confirmed BleepingComputer · Nov 17, 13:21

Researchers hijack Kokoro TTS model's Hugging Face account via an expired domain

Alon Hertz and his team registered hexgrad.com, the lapsed domain listed in Kokoro's DONATE.md, and used it to reset the publisher's Hugging Face password. Kokoro-82M has about 13 million monthly downloads and is used in projects from Google, NVIDIA, AMD, Intel and AWS. They showed weights can be altered in 87 seconds on a gaming GPU so the model speaks different words than its input, without changing application code, and that Hugging Face would not flag such an update; they did not upload the altered weights.

Why it matters to you

Model hubs have the same account-takeover risks as package registries, but weight changes are harder to review than code. Abandoned projects with expired domains are easy targets.

Action

Pin Hugging Face models to a specific commit revision and verify file hashes, mirror critical models internally, and track maintainer activity for models you depend on.

medium Confirmed GitHub Security Lab · Nov 17, 13:29

GitHub and Microsoft turn ~9,800 AI findings into 99 verified reports; 55 already fixed

In the Codename MDASH pilot, Microsoft's agentic scanning harness scanned six open-source projects (AutoGPT, Caddy, Express, FastMCP, ImageMagick and Netty) and proposed fixes. A GitHub Security Lab triage agent deduplicated and validated the findings, seven Microsoft researchers checked the rest by hand, and 99 reports went out privately with proofs of concept and suggested fixes. By November 15 maintainers had fixed 55; Caddy fixed all 22 of its reports within a week.

Why it matters to you

AI vulnerability discovery is producing far more findings than maintainers can handle. The pilot suggests the useful unit is a verified report with a fix, and that manual verification is the current bottleneck.

Action

If you run AI scanning internally, measure fixes shipped rather than findings, and put a validation stage before anything reaches engineering teams.

Study: an AI agent extracted system-prompt secrets from about eight in ten of 363 models

high Confirmed AWS Security Bulletins · Nov 17, 15:11

AWS Private CA issuer for Kubernetes let one namespace sign with another namespace's CA

CVE-2026-130622 and CVE-2026-130623 in aws-privateca-issuer before 1.12.0 let an authenticated user who can create namespace-scoped issuers obtain certificates, including subordinate CA certificates, signed by another namespace's AWS Private CA using that namespace's stored AWS credentials. The flaw is incorrect authorization in credential loading for namespace-scoped issuers.

Why it matters to you

Namespaces are a common tenant boundary, and cluster controllers that hold credentials for many tenants can break it with one missing check. A subordinate CA certificate from another tenant's CA is a full trust compromise for anything that trusts that CA.

Action

Upgrade aws-privateca-issuer to 1.12.0 or later, review certificates issued by each Private CA for unexpected subordinates, and limit who can create issuers.

  • Name constraints and path length on subordinate CAs

medium Confirmed GitHub Advisory Database (critical/high) · Nov 17, 16:00

SimpleSAMLphp SAML2 fix incomplete: unsigned embedded Response still bypasses artifact checks

The fix for CVE-2026-49283, a cross-IdP authentication bypass in the SAML2 library's HTTP-Artifact binding, only verifies the embedded Response's signature when the Response is signed. An unsigned embedded Response skips verification, and the library does not bind the embedded Issuer to the expected IdP. The advisory rates it CVSS 8.7 and affects the released v6.2.3.

Why it matters to you

SAML bugs repeatedly come from verification that runs only if a signature is present. A fix that checks signatures without requiring them leaves the original bypass open.

Action

Watch for a patched SAML2 release and, until then, require signed Responses in IdP and SP configuration where possible.

critical Confirmed Wiz Blog & Research · Nov 17, 17:03

Malicious agent-framework 1.26.1 and 1.26.2 on PyPI stole Azure, CI and cloud credentials

On November 17, versions 1.26.1 and 1.26.2 of Microsoft's agent-framework package (about 200,000 downloads a month) were published with a credential stealer and removed about an hour later. A .pth file ran the payload on every Python start, even without importing the package, collecting secret-like environment variables, secrets from other processes, credential files (Azure CLI, .npmrc, .git-credentials, Docker, Hugging Face tokens), Azure DevOps OIDC tokens and managed-identity tokens; 1.26.2 also stole GitHub Actions OIDC tokens. How the versions were published is unconfirmed; 1.26.1 had no matching tag or release and was wheel-only.

Why it matters to you

AI agent frameworks run in CI and cloud workloads full of high-value credentials, which makes them prime supply-chain targets. OIDC and managed-identity tokens remove long-lived keys, but a process running inside the workload can still mint and exfiltrate them.

Action

Search lockfiles, CI logs, virtual environments and images for agent-framework 1.26.1 or 1.26.2; pin 1.26.0; rotate every secret reachable from affected hosts and runners; review Azure sign-ins for managed identities and Entra federated credentials used by affected workflows.

  • Scoping OIDC federation for CI workloads

critical Confirmed Wiz Blog & Research · Nov 17, 18:15

Java4Shell: OpenJDK AVX-512 Base64 bug enables pre-auth RCE in major Java apps (CVE-2026-114938)

A bounds miscalculation in the JVM's AVX-512 VBMI-optimized Base64 decoding intrinsic causes a heap out-of-bounds write when input has unexpected trailing padding, rated CVSS 9.2. It affects OpenJDK 17.0.6 and later and downstream distributions on x86-64 CPUs with AVX-512 VBMI; ARM64 is not affected. Wiz lists Jira, Confluence, Keycloak, Artifactory and Jenkins as proven vulnerable to pre-auth RCE, and says its AI harness built a proof of concept within two hours. Calif discovered it; no public exploit or in-the-wild use is reported.

Why it matters to you

A bug in a JIT intrinsic is reachable from any code path that decodes attacker-controlled Base64, which is nearly every web app and identity system. It also shows exploitation speed: an AI harness produced a working exploit before full details were public.

Action

Apply the November 17 Java updates. Until then, set -XX:-UseBASE64Intrinsics (or -XX:UseAVX=2) on affected x86 hosts and restrict access to exposed management portals; WAF rules are unlikely to cover all paths.
